# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Lokalt is a single front door for Helsinki residents who want to make their voice heard about something happening in their city. They describe their concern in their own words (Swedish, Finnish, or English), and the app triages it: things that are broken get pointed to the city's existing fault-report channel, personal/legal matters get pointed to the right statutory channel, and brand-new ideas get pointed to citizen-initiative style channels. The product's real depth is reserved for the **policy** case — when the resident wants the city to decide something differently, Lokalt identifies which municipal body actually owns that decision, surfaces a real contact, and drafts a short email the resident sends themselves via a `mailto:` link. It never sends email, requires no accounts, and stores no user data. See [README.md](README.md) for the full product description and setup instructions.

## Commands

```bash
npm run dev      # start dev server at http://localhost:3000
npm run build    # production build
npm run lint      # next lint

npm run generate:bodies    # regenerate data/bodies.json from paatokset_policymakers
npm run backfill:palaute   # one-off: ingest N days of Open311 history into feedback_reports (default 365)
npm run classify:palaute   # one-off/recurring: tag untagged feedback_reports rows with the fixed taxonomy
```

There is no test suite. Requires `ANTHROPIC_API_KEY` and `SUPABASE_URL`/`SUPABASE_ANON_KEY` in `.env.local` (copy from `.env.local.example`) to exercise the API routes locally.

## Architecture

**Two-call Claude pipeline, split by responsibility:**

1. `POST /api/route-question` ([src/app/api/route-question/route.ts](src/app/api/route-question/route.ts)) — classifies the resident's free text into one of four **tracks** (`operational`, `policy`, `statutory`, `agenda`) using the system prompt in [src/lib/classify-prompt.ts](src/lib/classify-prompt.ts). Only for the `policy` track does the model also pick a `body_id` from the supplied list of committees. This routing exists because Helsinki's lautakunder/nämnder only decide policy — they must never receive infrastructure-repair reports or personal/legal/health complaints (those have separate statutory channels).
2. `POST /api/draft` ([src/app/api/draft/route.ts](src/app/api/draft/route.ts)) — writes the actual email/text draft (`policy` mode has a recipient; `agenda` mode does not), in the first person, under 150 words, with bracketed placeholders (`[din adress]`) for anything personal.

**The model never sees or produces contact data.** The classifier is only allowed to output an `id` string; [src/lib/bodies.ts](src/lib/bodies.ts)'s `bodiesForPrompt()` deliberately strips names/emails/phones before building the prompt, and the route handler re-validates any returned `body_id` against the known set in `data/bodies.json`, nulling it out if it's not a real id or the track isn't `policy`. This is the core invariant to preserve when touching either API route: names and email addresses are looked up locally, never generated.

**Body data**: [data/bodies.json](data/bodies.json) is generated by [scripts/generate-bodies.mjs](scripts/generate-bodies.mjs) from the city's live `paatokset_policymakers` index (see [lokalt-kontext/claude-kontext/01-datakallor.md](lokalt-kontext/claude-kontext/01-datakallor.md)), filtered to committees/sections/board/council (`Lautakunta`/`Jaosto`/`Hallitus`/`Valtuusto`) and excluding all office-holders. Each entry carries a `routable` flag — only the ~10 bodies a resident's everyday concern should reach (the four sector committees, city board, city council, HKL's board, and the culture/library, sports and youth sections) are `routable: true`, and only those are ever offered to the classifier (`bodiesForPrompt()` in [src/lib/bodies.ts](src/lib/bodies.ts) filters on it). Remit text, plain-language `topics_sv`/`topics_fi`/`topics_en`, and named chairs are hand-authored on top of the generated identity fields — the live index carries none of that — and live in `HAND_CONTENT` inside the generator script, re-applied on every regeneration. Chairs are published office-holders; leave `email` `null` rather than guessing one.

**Shared Claude client**: [src/lib/anthropic.ts](src/lib/anthropic.ts) exports a single `MODEL` constant, a lazily-constructed client that reads `ANTHROPIC_API_KEY` server-side only, and `parseJsonLoose()` since both routes require the model to return raw JSON (defensively strips stray ``` fences).

**i18n**: no library — [src/lib/i18n.ts](src/lib/i18n.ts) is a flat dictionary of Swedish/Finnish/English strings (`Lang` = `"sv" | "fi" | "en"`); Swedish is the default language throughout.

## City-data lookups (Supabase-backed)

Beyond the two Claude calls above, `/app` also does live lookups against Helsinki's open data, per [lokalt-kontext/claude-kontext/](lokalt-kontext/claude-kontext/). Each is cached in Supabase (env vars `SUPABASE_URL`/`SUPABASE_ANON_KEY`) and degrades to "we couldn't determine/find X" rather than erroring the page when the upstream service is down — never a blank screen, never a false "not reported" claim.

- **Area responsibility** ([src/lib/area-responsibility.ts](src/lib/area-responsibility.ts), `/api/area-responsibility`): WFS lookup against `avoindata:YLRE_Katu_ja_viherosat_kaikki_alue`. The `cql_filter` geometry literal must be written `SRID=4326;POINT(lon lat)` — a bare `POINT(...)` is silently evaluated in the layer's native CRS (not `srsName`, which only affects output) and always returns zero results. Cached in `area_responsibility_cache` keyed by rounded coordinates.
- **Street geocoding** ([src/lib/geocode-street.ts](src/lib/geocode-street.ts), `/api/geocode-street`): median centroid of WFS polygons matching `alueen_nimi ILIKE '%name%'`. Known limitation: taking the median of lat and lon independently (as specified) can land off any actual polygon for narrow or curving streets — surfaces as an honest "couldn't determine", not a crash.
- **Decisions** ([src/lib/decisions.ts](src/lib/decisions.ts), `/api/decisions`): full-text search against `paatokset_decisions` (Elasticsearch via `https://paatokset-elastic-proxy.api.hel.ninja` — an operational domain, not a published API; can move without notice). Every field in a hit comes back as a single-element array, never a bare scalar. Cached per query in `decisions_cache`, 10-minute TTL.
- **Nearby reports** ([src/lib/nearby-reports.ts](src/lib/nearby-reports.ts), `/api/nearby-reports`): the real (not simplified) version of step 4 in `02-byggordning.md`. `feedback_reports` (Postgres, PostGIS `geography` + `pg_trgm`) holds twelve months of Open311 reports, ingested by the deployed Supabase Edge Function `ingest-palaute` (`{mode:"recent"}` for the last 3 days, `{mode:"day", date}` for backfill). **Not on a schedule yet** — `{mode:"recent"}` must be invoked manually (or from a cron you set up) to keep the data fresh past the initial backfill date; this was a deliberate choice to defer until hosting/deployment is decided, not an oversight. See [scripts/backfill-palaute.mjs](scripts/backfill-palaute.mjs) (one-off, drives the function one day at a time) and [scripts/classify-palaute.mjs](scripts/classify-palaute.mjs) (separate step, never blocks ingestion, batches of 50 through a cheap model against a fixed taxonomy). Search is two steps: the `search_nearby_reports` Postgres function (`ST_DWithin` + `pg_trgm` `similarity`, radius escalating 300m→800m) returns up to 20 candidates, then — only when the resident has typed their own text — a cheap model call labels each candidate `samma`/`kanske`/`annat` against that text and only `samma`/`kanske` are shown; a failed model call falls back to the unverified step-A ranking rather than erroring. `status_notes` from Open311 is raw HTML (`<div>`, `<a href>`, `&nbsp;`) and is stripped to plain text before display. **This covers roughly one eighth of the city's actual report volume** ([lokalt-kontext/claude-kontext/01-datakallor.md](lokalt-kontext/claude-kontext/01-datakallor.md)) — the UI must never say "not reported", only "no published report found".

## Conventions

- Path alias `@/*` maps to `src/*` (see [tsconfig.json](tsconfig.json)).
- Server routes run on `export const runtime = "nodejs"` and must keep `ANTHROPIC_API_KEY` server-side — never expose it to the client.
- When editing the classify or draft system prompts, preserve the "hard rules" structure (JSON-only output, no invented contact details, bracketed placeholders for personal info) — these are safety constraints, not style choices.
